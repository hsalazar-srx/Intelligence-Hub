## Conventions

### Signal files
- Location: `signals/YYYY-MM-DD-short-title.md`
- Frontmatter fields: `date`, `title`, `source`, `topic`, `tags`, `project`, `relevance`, `video_url` (if YouTube)
- Project values: `digital-transformation` | `ai-platform` | `m3-erp-integration` | `general`
- Relevance values: `high` | `medium` | `low`
- Auto-generated signals land in `signals/drafts/` and need PR review before moving to `signals/`

### Project tags
| Tag | Use for |
|-----|---------|
| `digital-transformation` | MES modernization, org change, process digitization |
| `ai-platform` | LLM research, RAG, MLOps, AI platform architecture |
| `m3-erp-integration` | Infor M3, ERP patterns, data contracts |
| `general` | Relevant but not project-specific |

### Build
```bash
python3 scripts/build.py        # regenerates docs/index.html from all markdown
```
Push to `main` → GitHub Actions builds and deploys automatically.

### Adding a YouTube channel
Edit `channels.yml` — add one entry with `name`, `channel_id`, `project_hint`, `priority`.
No code changes needed. Tracker picks it up next Monday run.

## Key Architectural Decisions (already made — don't revisit without reason)

1. **Static site over CMS** — GitHub Pages + Python build script. Simple, version-controlled, free.
2. **PR review workflow** — YouTube auto-signals create PRs, never commit directly to main. Human reviews before publishing.
3. **Medium relevance filter** — enterprise AI broadly, not just manufacturing-specific. Startups/greenfield/consumer content is filtered out.
4. **Python build script** — not Node/npm, because GitHub Actions environment has Python built-in (avoids npm install step in CI).
5. **Pre-commit hook** — runs locally. GitHub Actions Gitleaks runs server-side. Two independent layers.
6. **Tweet capture is manual** — Twitter API costs $100/month. Team pastes URLs into a capture form instead.

## What NOT to Do

- Don't edit `docs/index.html` manually — it gets overwritten by `build.py`
- Don't commit `.env` files, private keys, or internal IP addresses
- Don't fine-tune LLMs for enterprise knowledge — use RAG instead
- Don't add channels to the tracker without a `channel_id` — it will silently skip
- Don't merge auto-generated signal PRs without reading them — they need human review
